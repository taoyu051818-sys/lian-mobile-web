# Badge & Chip Presenter Contract

Issue: #188
Scope: Status, type, badge, and chip presenter mappings
Created: 2026-05-08
Status: Draft

This contract defines how domain state maps to UI badge and chip presentation. It covers taxonomy, presenter output shape, unknown fallbacks, AI/official badge semantics, accessibility descriptions, and semantic tone mapping.

Source components: `src/ui/TypeChip.vue`, `src/ui/TrustBadge.vue`, `src/ui/TagChip.vue`, `src/ui/LocationChip.vue`, `src/ui/IdentityBadge.vue`
Design source: `docs/design/LIAN-Campus-UI-UX-Guidelines-V0.1.md`

---

## 1. Taxonomy

Domain enums must not be defined inside UI primitives. Each taxonomy below is a domain-level union that presenters consume. UI primitives accept only visual props (`tone`, `size`, `variant`).

### 1.1 ContentType

Content classification for feed items and cards.

| Value | Chinese Label | Description |
|---|---|---|
| `experience` | 经验 | Campus life tips, how-tos, reviews |
| `discussion` | 讨论 | Open discussion, Q&A, debate |
| `hot` | 热帖 | Trending or high-engagement post |
| `food` | 饭堂 | Food stall, dining hall, merchant |
| `place` | 地点 | Place-related content or place card |
| `ai` | AI 摘要 | AI-organized or AI-summarized content |
| `official` | 官方 | Platform-issued official notice or update |
| `trade` | 拼车/闲置 | Carpool, secondhand, trade post |
| `contribution` | 贡献 | User contribution, correction, edit |
| `default` | 帖子 | Unclassified or generic content |

### 1.2 TrustTone

Trust or verification status for content, places, and identities.

| Value | Chinese Label | Description |
|---|---|---|
| `confirmed` | 已确认 | Verified by source, merchant, or moderator |
| `pending` | 待确认 | Submitted but not yet verified |
| `disputed` | 有争议 | Conflicting reports or corrections exist |
| `expired` | 已过期 | Information may be outdated |
| `ai` | AI 整理 | Organized or generated by AI |
| `official` | 官方信息 | Authored or endorsed by platform |

### 1.3 PlaceType

Place category for location chips and place cards.

| Value | Chinese Label | Description |
|---|---|---|
| `dining` | 食堂 | Dining hall or food court |
| `building` | 教学楼 | Academic building |
| `dormitory` | 宿舍 | Residential area |
| `landmark` | 地标 | Notable campus landmark |
| `merchant` | 商家 | Off-campus merchant or shop |
| `poi` | 地点 | Generic point of interest |

### 1.4 Visibility

Post visibility scope.

| Value | Chinese Label | Description |
|---|---|---|
| `public` | 公开 | Visible to all campus users |
| `followers` | 关注可见 | Visible to followers only |
| `private` | 仅自己 | Private draft or note |

### 1.5 SourceKind

Origin of content for trust labeling.

| Value | Chinese Label | Description |
|---|---|---|
| `user` | 用户发布 | User-authored content |
| `merchant` | 商家更新 | Merchant-provided information |
| `operator` | 运营维护 | Platform operator update |
| `aiGenerated` | AI 生成 | Entirely AI-generated |
| `aiAssisted` | AI 辅助 | AI-assisted user content |
| `aiSummary` | AI 整理 | AI-summarized from multiple sources |
| `system` | 系统 | System-generated content |

### 1.6 PermissionState

Access or authorization state for content, features, and audience-scoped surfaces.

| Value | Chinese Label | Description |
|---|---|---|
| `granted` | 已授权 | Access confirmed for current user |
| `denied` | 无权限 | Access explicitly denied |
| `restricted` | 受限访问 | Access scoped to school, org, or role |
| `pending` | 待审核 | Awaiting approval or verification |
| `expired` | 已过期 | Permission or access window has lapsed |
| `public` | 公开 | No restriction, publicly accessible |

### 1.7 UI Primitive Boundary Rule

Domain enums (`ContentType`, `TrustStatus`, `PlaceType`, `Visibility`, `PermissionState`, `SourceKind`) MUST NOT be defined, re-exported, or referenced inside `src/ui/**`. UI primitives accept only:

- Visual props: `tone: SemanticTone`, `size`, `variant`
- Rendered content: `label: string`, `icon: string`
- Accessibility: `ariaLabel: string`

If a UI primitive receives a domain enum, the boundary is violated. Domain-to-visual mapping lives exclusively in presenter functions outside `src/ui/`.

## 2. Presenter Output Shape

Each domain presenter produces a uniform output object. UI components consume this shape; they do not compute it.

```ts
interface PresenterOutput {
  /** Display label shown inside the chip/badge */
  label: string;
  /** Semantic tone key — maps to design tokens, not CSS classes */
  tone: SemanticTone;
  /** Decorative icon character or empty string */
  icon: string;
  /** Full-text description for tooltip or expanded context */
  description: string;
  /** Accessible label for screen readers */
  ariaLabel: string;
  /** i18n copy key for label lookup */
  copyKey: string;
}
```

### 2.1 Required Presenters

| Presenter | Input Taxonomy | Output |
|---|---|---|
| `presentContentType(type: ContentType)` | ContentType | `PresenterOutput` |
| `presentTrustStatus(tone: TrustTone)` | TrustTone | `PresenterOutput` |
| `presentPlaceType(type: PlaceType)` | PlaceType | `PresenterOutput` |
| `presentVisibility(vis: Visibility)` | Visibility | `PresenterOutput` |
| `presentPermissionState(state: PermissionState)` | PermissionState | `PresenterOutput` |
| `presentSourceKind(kind: SourceKind)` | SourceKind | `PresenterOutput` |

### 2.2 Presenter Rules

- Presenters are pure functions: same input always produces same output.
- Presenters do not import Vue, React, or any UI framework.
- Presenters do not access stores, APIs, or browser globals.
- Presenters return the unknown fallback (section 3) for unrecognized input.

## 3. Unknown Fallbacks

When a presenter receives a value not in its taxonomy:

```ts
const UNKNOWN_FALLBACK: PresenterOutput = {
  label: "其他",
  tone: "neutral",
  icon: "",
  description: "未识别的类型",
  ariaLabel: "未识别的类型",
  copyKey: "common.unknown",
};
```

### 3.1 Fallback Rules

- Unknown values must never produce empty labels or missing `ariaLabel`.
- Unknown values must use the `neutral` tone — never `danger` or `warning`.
- Unknown values are logged to diagnostics (dev mode only) with the raw value.
- The UI must render the fallback chip/badge, not hide it.
- When the backend introduces a new enum value, the fallback ensures graceful degradation until the frontend adds explicit mapping.

### 3.2 Deprecated Values

Deprecated taxonomy values should map to their closest active equivalent or to the unknown fallback. The presenter must not throw or return `null`.

## 4. AI and Official Badge Semantics

These badges carry strong trust implications. Their use is governed by strict rules.

### 4.1 AI Badge (`tone: "ai"`)

| Rule | Detail |
|---|---|
| Allowed source | Only `SourceKind.aiGenerated`, `aiAssisted`, `aiSummary` |
| Label variants | `AI 摘要`, `AI 辅助`, `AI 生成` — distinct per source kind |
| Must not imply | Factual authority, editorial endorsement, or platform verification |
| Required disclosure | Source count, uncertainty note, link to sources |
| No-source rule | AI content without sources renders as draft, not as badge |

AI badge copy patterns:

| SourceKind | Label | Description |
|---|---|---|
| `aiSummary` | AI 摘要 | 根据 N 条讨论整理 · 可能不准确，请查看来源 |
| `aiAssisted` | AI 辅助 | 内容由 AI 辅助生成 · 请核实关键信息 |
| `aiGenerated` | AI 生成 | 内容由 AI 生成 · 仅供参考 |

### 4.2 Official Badge (`tone: "official"`)

| Rule | Detail |
|---|---|
| Allowed source | Only backend-authorized `official` flag — never frontend-inferred |
| Label | 官方 or 官方通知 |
| Must not imply | Endorsement of user-generated content |
| Usage restriction | Platform notices, verified merchant updates, operator-curated content |

### 4.3 Trust Badge Semantics

| Tone | User-facing meaning | When to use |
|---|---|---|
| `confirmed` | This information has been verified | Merchant update confirmed, place info verified |
| `pending` | This information is awaiting verification | New user correction, recent submission |
| `disputed` | Conflicting information exists | Multiple corrections, conflicting reports |
| `expired` | This information may be outdated | Stale data, time-limited info past threshold |
| `ai` | Organized by AI, may be inaccurate | AI summaries, AI-generated drafts |
| `official` | From the platform or verified source | Official notices, operator updates |

## 5. Accessibility Descriptions

Every badge/chip must provide a text alternative that conveys the same semantic meaning as the visual presentation.

### 5.1 ariaLabel Requirements

- `ariaLabel` must be in the user's current locale.
- `ariaLabel` must describe the *state*, not the *appearance*. Use "内容由 AI 辅助生成" not "紫色标签".
- `ariaLabel` must not duplicate the visible label verbatim — it should add context the label omits.

### 5.2 Description Requirements

- `description` is used for tooltip or expanded context.
- `description` must include the *why*: "待确认 — 用户投稿，暂未核实" not just "待确认".
- For trust badges, `description` must explain what the state means and what the user can do next.

### 5.3 Required ariaLabel Patterns

| Presenter | Example ariaLabel |
|---|---|
| `presentContentType("ai")` | "AI 摘要内容" |
| `presentContentType("official")` | "官方通知" |
| `presentTrustStatus("pending")` | "待确认 — 用户投稿，暂未核实" |
| `presentTrustStatus("disputed")` | "有争议 — 存在不同说法" |
| `presentTrustStatus("expired")` | "已过期 — 信息可能不再准确" |
| `presentTrustStatus("ai")` | "AI 整理 — 可能不准确" |
| `presentPlaceType("dining")` | "食堂" |
| `presentPermissionState("denied")` | "无权限 — 当前用户无法访问" |
| `presentPermissionState("restricted")` | "受限访问 — 仅限特定群体" |
| `presentPermissionState("pending")` | "待审核 — 等待审批" |
| `presentPermissionState("expired")` | "已过期 — 权限已失效" |

### 5.4 Color Independence

- Badge/chip must not rely on color alone to convey state.
- Every state must have a text label, icon, or both.
- In high-contrast mode, tone mapping must preserve distinguishability without relying on hue shifts.

### 6.3 Tone Rules

- UI primitives must accept `SemanticTone`, not domain enum values.
- New domain values map to existing semantic tones — do not add tones per domain value.
- Adding a new semantic tone requires updating the token table above and all three theme columns.
- Tones are not CSS classes. The primitive resolves tone to CSS class via a lookup, keeping the mapping centralized.

## 8. Acceptance Criteria

- [ ] Domain enums are not defined inside UI primitive components (`src/ui/**`).
- [ ] Each taxonomy (ContentType, TrustStatus, PlaceType, Visibility, PermissionState, SourceKind) has a presenter function returning `PresenterOutput`.
- [ ] Unknown enum values produce the fallback output, not empty or null.
- [ ] AI badges distinguish `aiGenerated`, `aiAssisted`, `aiSummary` with distinct labels.
- [ ] Official badges are driven only by backend-authorized fields.
- [ ] Every badge/chip provides `ariaLabel` with state-level description.
- [ ] Semantic tone mapping is documented and covers all taxonomy values.
- [ ] Tones include light, dark, and high-contrast token values.
- [ ] UI primitives accept `SemanticTone`, not domain enums.
- [ ] `presentPermissionState` covers all six states with correct tone mapping.
- [ ] UI primitive boundary rule (§1.7) is enforced — no domain enum imports in `src/ui/**`.
